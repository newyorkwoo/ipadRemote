# iPad Remote — 用 iPad 遠端控制家裡的 Mac

純 Swift 實作，兩個 App：

| Target | 平台 | 角色 |
|---|---|---|
| **MacAgent** | macOS 14+ | 選單列常駐程式：擷取螢幕與系統聲音、H.264 / AAC 編碼、接收並執行滑鼠鍵盤事件、切換輸入法 |
| **iPadRemote** | iPadOS 17+ | 遙控端：顯示畫面、觸控 / 觸控板 / 實體鍵盤操作、Wake‑on‑LAN、自動重連 |

## 功能

- **加密連線**：TLS 1.2 ECDHE‑PSK（`TLS_ECDHE_PSK_WITH_CHACHA20_POLY1305_SHA256`），具前向保密：即使金鑰日後外洩，也解不開先前錄下的連線。
- **一次性配對碼 + 每台 iPad 專屬金鑰**：配對碼為 20 字元（約 100 bits），只用於第一次配對。配對成功後 Mac 發給這台 iPad 一把 256‑bit 專屬金鑰，並自動更換配對碼。之後每次連線，iPad 都用這把金鑰交握，並以綁定該連線的 HMAC 證明身分。Mac 選單列可以個別移除 iPad，被移除的 iPad 立即中斷且無法再連線，其他 iPad 不受影響。金鑰兩端都存在鑰匙圈（僅限本機，不進 iCloud）。
- **其他保護**：iPad App 開啟、或離開超過 30 秒後回來，需要 Face ID / 密碼解鎖（可在「我的 Mac」右上角選單關閉），鎖定時不會送出任何輸入。有 iPad 開始控制或新配對時，Mac 會跳出通知，選單列可以一鍵中斷連線。貼上的文字只放在本機剪貼簿、標記為機密，貼上後立即還原。配對碼預設隱藏，拷貝後 60 秒自動清除。
- **喚醒休眠中的 Mac**：Wake‑on‑LAN 魔術封包（廣播 + 子網廣播 + 最後已知 IP + 自訂外部位址）。連不上時 App 會**自動**送出喚醒封包並持續重試。連線期間 Mac 會保持喚醒，並提供「點亮螢幕」按鈕。
- **自動重連**：每 2 秒送一次心跳，7 秒沒回應就判定斷線。採用指數退避（0.5 秒到 5 秒），不會自己放棄。網路恢復或 App 回到前景時會立刻重連，同時保留最後一張畫面並顯示重連狀態。
- **聲音同步**：Mac 的系統聲音以 AAC 48 kHz 立體聲（約 128 kbps）和畫面一起傳到 iPad，收到即播放；播放緩衝超過 0.25 秒會丟棄，避免網路卡頓後聲音和畫面脫節。工具列喇叭按鈕可開關（Mac 本機仍會出聲）。
- **輸入法**：
  - 可以從 iPad 直接切換 Mac 的輸入法（列出 Mac 已啟用的所有輸入法），或切到下一個。
  - 文字輸入可以用 iPad 自己的輸入法（注音、倉頡、拼音、日文…）。在「即時」模式下，每選完一個字就送到 Mac（組字中的字不會送出）。「整段」模式則打完一段再送出。
  - 可改用剪貼簿貼上，適合 Mac 端輸入法攔截文字的情況。
  - 接上實體鍵盤時，按鍵以原始鍵碼送出，所以也可以直接用 **Mac 端的輸入法**打字。
  - ⚠️ 請關閉 iPad 的「設定 › 輔助使用 › 鍵盤 › **全鍵盤控制**」。開啟時系統會攔截空白鍵、Tab、方向鍵（畫面四周出現藍框），App 收不到這些按鍵，注音也打不出一聲。
- **操作**：
  - 直接觸控：點一下是左鍵，連點是雙擊，兩指點是右鍵，長按拖移是拖曳，兩指滑動是捲動。
  - 觸控板模式：手指相對移動游標。
  - 巧控鍵盤的觸控板與滑鼠：游標、右鍵、捲動、拖曳都支援。
- **蘋果風格介面**：SwiftUI、SF Symbols；iPadOS 26 以上使用 Liquid Glass，舊版本使用毛玻璃材質。工具列可以收合，另有常用快捷鍵選單、多螢幕切換和畫質切換。

## 建置

```bash
brew install xcodegen   # 若尚未安裝
xcodegen generate
open iPadRemote.xcodeproj
```

1. 在 `project.yml` 填入 `DEVELOPMENT_TEAM`，或在 Xcode 的 Signing 頁面選擇你的 Team，然後把兩個 bundle ID 改成你自己的。
2. 在 Mac 上執行 **MacAgent**，選單列會出現 iPad 圖示。
   - 授權「螢幕與系統錄音」和「輔助使用」（選單裡有按鈕）。
   - 勾選「登入時啟動」。
3. 在 iPad 上執行 **iPadRemote**。在同一個 Wi‑Fi 下，「附近的 Mac」會自動出現；點一下並輸入配對碼即可。

## 讓 Mac 可以被喚醒（重要）

在 Mac 上執行：

```bash
sudo pmset -a womp 1          # 網路喚醒 (Wake on Magic Packet)
sudo pmset -a tcpkeepalive 1
```

也可以到「系統設定 › 能源」開啟「網路存取時喚醒」。

| 情境 | 可行性 |
|---|---|
| iMac / Mac mini / Mac Studio **有線網路** | ✅ Wake‑on‑LAN 最穩定 |
| Mac 透過 Wi‑Fi，家中有 **Apple TV / HomePod**（睡眠代理） | ✅ 連線請求會由睡眠代理喚醒 Mac |
| MacBook 闔上蓋子、**沒接電源** | ❌ 硬體上無法被網路喚醒 |
| MacBook 接電源、蓋子打開或接外接螢幕 | ⚠️ 大多可以；Wi‑Fi 喚醒依機型而定 |

> **Wi‑Fi 私密位址**：macOS 預設在每個 Wi‑Fi 網路使用「私密 Wi‑Fi 位址」，網路上看到的 MAC 和硬體 MAC 不同，而且一般程式讀不到這個私密位址。Agent 會盡量讀取私密位址，同時一定會送出硬體 MAC，所以 iPad 會對兩個位址都發送喚醒封包。最穩定的做法是到「系統設定 › Wi‑Fi › 家裡網路的詳細資訊」，把「私密 Wi‑Fi 位址」設為**關閉**。

## iPad 與 Mac 在不同網路（建議設定）

1. **兩台都安裝 [Tailscale](https://tailscale.com/download)**，並登入同一個帳號。不用設定路由器，電信業者共用 IP（CGNAT）也能連，連線另外有 WireGuard 加密。
2. Mac 選單列 › **開啟「遠端待命」**（預設開啟），並保持 **接電源、上蓋打開**（或接外接螢幕）。
   - 螢幕會照常關閉省電，但系統不會睡眠，iPad 從任何網路連入時會自動點亮螢幕。
   - 接電源時 MacBook 待命大約只用幾瓦。macOS 用電池時會忽略這個設定。
3. 在 iPad 加入 Mac 時，「從不同網路連線」欄位填入 Mac 選單列顯示的 **Tailscale 位址（100.x.x.x）**。
4. 成功連線一次後，App 會記住 Mac 的所有位址（區網 + Tailscale）。之後換到任何網路，都會**同時嘗試所有位址**，用最先連上的那條。

### 為什麼不靠 Wake-on-LAN？

魔術封包是區網廣播，從別的網路送不進家裡，而 Tailscale 也不會轉送廣播。Mac 一旦真正睡著，Tailscale 也會跟著離線。所以跨網路時最可靠的做法是「遠端待命」：Mac 只關螢幕、不睡眠。

如果你一定要讓 Mac 完全睡眠，還能從外部叫醒它，有以下選擇：
- 家中有 **Apple TV / HomePod**（睡眠代理），再加上路由器把 TCP 52800 轉發到 Mac。連線請求會由睡眠代理喚醒 Mac。⚠️ 不建議：這會把 Mac 的連接埠直接暴露在網際網路上。雖然沒有金鑰無法完成交握，仍會成為公開的攻擊面。請優先使用 Tailscale 搭配「遠端待命」。
- 家中有一台常開的裝置（樹莓派、NAS）幫忙轉送喚醒封包，然後在 App 的「外部喚醒位址」填它的位址。
- 部分路由器可以把 UDP 埠轉發到區網廣播位址。

## iOS 廣播權限

iOS 送出 UDP **廣播**封包需要 Apple 核准的 `com.apple.developer.networking.multicast` entitlement（[申請頁面](https://developer.apple.com/contact/request/networking-multicast)）。核准後，在 `project.yml` 取消 `CODE_SIGN_ENTITLEMENTS` 那行的註解即可。

沒有這個 entitlement 時，廣播封包會被系統擋下，但**單播到最後已知 IP**和**外部喚醒位址**仍然可以送出。

## 架構

```
iPad                                              Mac
┌───────────────────────┐   ECDHE-PSK/TCP 52800   ┌─────────────────────────┐
│ RemoteClient          │◀═══════════════════════▶│ RemoteServer (Bonjour)  │
│  ├ 心跳 / 重連 / WoL    │   [type][len][payload]  │  └ ClientSession         │
│  ├ VideoRenderer       │◀── H.264 (AVCC) ────────│     ├ ScreenStreamer     │
│  │  AVSampleBuffer...  │                         │     │  SCStream→VTEncoder │
│  └ RemoteCanvasView    │── JSON 控制訊息 ───────▶│     ├ InputInjector       │
│     手勢 / 實體鍵盤      │                         │     │  CGEvent           │
└───────────────────────┘                         │     └ InputSourceManager  │
                                                  │        TIS (Carbon)      │
                                                  └─────────────────────────┘
```

- `Shared/`：兩端共用的協定（`Protocol.swift`）、分框（`Framing.swift`）、加密參數（`SecureTransport.swift`）、影像封包格式和鑰匙圈工具。
- **低延遲設計**：
  - Mac 使用硬體低延遲 H.264（Constrained High、不重排幀、編碼器內不排隊，本機實測每幀約 6 ms）。
  - 關鍵幀只在需要時送出（連線、切換畫質、解碼失敗），避免定期的大封包造成卡頓。
  - 流量控制：iPad 每收到一幀就回報 `videoAck`，Mac 最多只讓 4 幀「在路上」，超過就在**編碼前**略過新幀；網路空出來後立刻補送最新畫面，不會停在舊畫面。這樣網路變慢時延遲不會越積越多。
  - iPad 在獨立的高優先權佇列解碼與顯示，不受主執行緒 UI 工作影響。
  - 畫面靜止時不送新幀，因此很省流量。

## 已知限制

- Mac 停在**登入視窗**（重新開機後、尚未登入）時，使用者層級的 App 無法擷取畫面或注入事件。這種情況需要搭配系統內建的「螢幕共享」。
- **跨網路時最需要先實測的一點**：螢幕關閉後如果 Mac 自動鎖定，鎖定畫面的密碼欄位啟用了 Secure Input，有可能擋下模擬的鍵盤輸入。建議連線期間讓 Mac 保持喚醒（App 已自動處理），或調整「螢幕保護程式啟動後要求密碼」的時間。
- iPadOS 會攔截部分系統快捷鍵（例如 ⌘Tab、⌘Space）。這些可以改用工具列的「⌘」選單送出。
- 聲音只從 Mac 傳到 iPad（不含麥克風），Mac 本機喇叭仍會同時出聲。
